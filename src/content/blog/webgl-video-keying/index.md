做 About 页的时候，我手里只有一段 8 秒的牡丹绽放视频：**360×418**，背景是从近黑到石板灰的渐变。而整个网站是浅紫色的。

最直接的做法是把视频放进一个画框里，但那样它就只是「贴在页面上的一个矩形」。我想要的是花本身浮在页面上，没有边界。

## 为什么不能直接导出透明视频

正常流程是用 ffmpeg 抠图，导出带 alpha 通道的 WebM（VP9）或 HEVC。但这台机器上没有 ffmpeg，而且就算导出了，浅紫色的页面上直接放一朵**黑底拍摄**的白花，暗部也会发灰发脏。

所以我换了个思路：**视频保持原样，抠图和调色都放到浏览器里，用 WebGL 每一帧实时做。**

## 关键观察：背景是固定的

这段视频的背景从头到尾都不变——只是一个竖向渐变。也就是说，**每一行**的背景色是确定的。

我从花苞那一帧的左边缘（那里一定是纯背景）按行采样，压成 32 个色标，作为一张 32×1 的查找表（LUT）传给 shader：

```js
// 视频背景从上到下的 32 个色标（近黑 → 石板灰）
const BG = "000003,000004,000004,010105,01020a,...,414650,3e444d".split(',');
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGB, BG.length, 1, 0, gl.RGB, gl.UNSIGNED_BYTE, lut);
```

## 抠图：颜色距离 + 冷暖

对每个像素，拿它和**同一行**的背景色比较：差得越远，越可能是花。

但花苞阶段的花瓣也非常暗，几乎和背景一样黑。这时候我用了第二个线索：**背景是冷色（偏蓝），花是暖色（偏红、偏黄）**。

```glsl
vec3 bg = texture2D(uLut, vec2(ty * 31.0/32.0 + 0.5/32.0, 0.5)).rgb;
float d = length(c - bg);                        // 和背景的颜色距离
float warm = (c.r - c.b) - (bg.r - bg.b);        // 比背景更"暖"多少
float a = smoothstep(0.05, 0.14, d + max(warm, 0.0) * 2.0);
```

半透明的边缘还要把背景「反混合」掉，否则花瓣边缘会有一圈黑边：

```glsl
vec3 fg = clamp((c - (1.0 - a) * bg) / max(a, 0.001), 0.0, 1.0);
```

## 调色：让它属于这个页面

抠出来的花还是「黑底拍摄」的颜色。我用了一个**亮度渐变映射**：

- 最暗 → 紫色 `#5b47b0`
- 中间 → 丁香色 `#b3a2ec`
- 最亮 → 近白 `#fffcff`

暗部先做一次开方拉伸，让花苞上的褶皱能看出来。只有「又亮又饱和」的颜色——也就是金色的花蕊——保留原色。这一步试了好几版：

1. 只给暗部上紫色 → 暗部和灰色中间调之间出现一条硬边，像色调分离；
2. 判断饱和度时没考虑亮度 → 暗褐色被当成「金色」保留，花苞上出现黑块；
3. 最后改成**整朵花统一映射**，并要求被保留的颜色足够亮，才得到一朵从紫色花苞绽放成白紫色、中心金黄的牡丹。

调参数时我没有直接在浏览器里试，而是先用 Python 写了一个一模一样的原型，把花苞、半开、盛开几帧并排渲染出来对比，确认之后再搬进 GLSL。

## 边缘和循环

- **羽化**：视频里贴边的花瓣和花茎底部会被画面裁掉，所以四边都乘一个 `smoothstep` 让它们自然淡出。
- **循环**：视频是「花苞 → 盛开」，直接 `loop` 会从盛开硬切回花苞。我放了两个隐藏的 `<video>`，在结尾前 1.2 秒让另一个从头播放，在 shader 里交叉淡化。
- **降级**：开启了「减少动态效果」，或者浏览器拒绝自动播放（后台标签页、iOS 低电量模式）时，显示一张同样抠好的静态盛开图；标签页重新可见或用户第一次交互时再尝试播放。

## 小结

当素材本身做不到你想要的效果时，可以先找出它**不变的部分**。这里不变的是背景渐变，有了它，抠图就变成了一个查表加比较的问题，几十行 shader 就能解决。
